# V0.1.001 UI And Station Input Change Requirements

## Purpose

This document describes the first Wave 1 iteration after the initial prototype.

The goal is to simplify the UI and make station creation more AI-friendly:

```text
Home screen modules should be simpler.
Practice setup should accept one structured copy-paste text block.
The tool should parse that text block into station title, scenario, and four questions.
```

## Change 1: Simplify Home Screen Module Cards

### What To Implement

On the home screen, each ability module should show only the module title.

Remove the subtitle / description text currently shown under each selected module card.

The home screen should still show all nine module titles:

```text
Motivation / Course Fit
Communication / Rapport
Professional Behaviour
Ethics / Decision-Making
Teamwork / Collaboration
Reflection / Feedback
Public Health / Social Awareness
De-technicalisation
Cultural Safety / Equity
```

### How To Implement

Keep the module selection logic unchanged.

Only adjust the presentation:

```text
1. Remove visible module description/subtitle text from the module cards/buttons.
2. Keep the module title readable and clickable.
3. Preserve selected module state after click.
```

### Completion Criteria

This change is successful when:

```text
1. The home screen shows the nine module titles.
2. No module subtitle/description appears under the titles.
3. Clicking a module still opens practice setup.
4. The selected module still flows into metadata, question.txt, and the practice screen.
```

### If Implementation Fails

If module selection breaks:

```text
1. Restore the previous module click/state logic.
2. Apply only the visual text removal again.
3. Re-test that selected module is saved correctly.
```

## Change 2: Replace Multiple Setup Fields With One Structured Text Input

### What To Implement

On the practice setup screen, replace the separate inputs for:

```text
Station title
Scenario / context
Question 1
Question 2
Question 3
Question 4
```

with one large textarea for a structured station text block.

The user should copy-paste the full station into this single textarea.

### Required Input Format

The pasted text must follow this exact labelled structure:

```text
Station Title:
[station title here]

Scenario / Context:
[scenario or context here]

Question 1:
[question 1 here]

Question 2:
[question 2 here]

Question 3:
[question 3 here]

Question 4:
[question 4 here]
```

The labels should be case-insensitive, but the recommended visible template should use the exact wording above.

The parser should allow multi-line content under each label until the next recognized label.

### How To Implement

The setup screen should show:

```text
Selected module title
Prompt/instruction text for generating a station
One large structured station textarea
Start Station button
```

When the user clicks `Start Station`, parse the textarea into:

```text
stationTitle
scenario
question1
question2
question3
question4
```

The parsed result should then feed the existing timing, recording, reflection, and storage flows.

## Change 3: Add AI-Friendly Prompt Above The Textarea

### What To Implement

Above the structured station textarea, show a short prompt that the user can give to AI when generating a station.

The prompt should explain the required station format.

### Suggested Visible Prompt

Use wording close to this:

```text
Ask AI to create one Melbourne-style MMI station for the selected module using exactly this format: Station Title, Scenario / Context, Question 1, Question 2, Question 3, Question 4. Paste the full formatted station below.
```

Then show a copyable template:

```text
Station Title:

Scenario / Context:

Question 1:

Question 2:

Question 3:

Question 4:
```

The prompt should be visible to anyone using the tool, so they know how to prepare station content before pasting it in.

### Completion Criteria

This change is successful when:

```text
1. The setup screen shows clear instructions above the textarea.
2. The required template is visible.
3. A user can copy the template or follow it manually.
4. The page clearly communicates that the full station should be pasted into one textarea.
```

## Parsing Requirements

### Valid Input

The app should accept this:

```text
Station Title:
Friend stealing at work

Scenario / Context:
You and your friend both started working in a sports store over the summer holidays. You recently noticed that your friend has started stealing shoes and sporting equipment.

Question 1:
What are the issues in this situation?

Question 2:
What would you do to address the situation?

Question 3:
You tried to speak to your friend, but he does not see a need to change his actions. What do you do?

Question 4:
Your friend tells you that he has been stealing to pay off a gambling debt. Does that change the situation?
```

It should parse into:

```text
stationTitle = Friend stealing at work
scenario = You and your friend...
question1 = What are the issues...
question2 = What would you do...
question3 = You tried to speak...
question4 = Your friend tells you...
```

### Required Fields

These fields are required:

```text
Station Title
Question 1
Question 2
Question 3
Question 4
```

Scenario / Context should be allowed to be empty, but the label should still appear in the recommended template.

### Error Handling

If parsing fails, do not start the station.

Show a clear message such as:

```text
The station text could not be parsed. Please use the required labels: Station Title, Scenario / Context, Question 1, Question 2, Question 3, Question 4.
```

If a required field is missing, show which field is missing:

```text
Missing: Question 3
```

Keep the user's pasted text intact so they can fix it.

## Save File Requirements After This Change

The saved files should remain the same:

```text
question.txt
answer.webm
reflection.md
metadata.json
```

However, `question.txt` should be generated from the parsed structured text.

The saved `question.txt` should still contain:

```text
Module
Station Title
Scenario
Question 1
Question 2
Question 3
Question 4
```

The parsed values should also continue flowing into `metadata.json`.

## End-To-End Completion Criteria

The full V0.1.001 change is successful when:

```text
1. Home screen module cards show title only.
2. Practice setup uses one structured textarea instead of six separate fields.
3. The setup page shows an AI-friendly prompt and template.
4. Valid structured station text parses correctly.
5. Invalid or incomplete station text produces a useful error.
6. The existing station timer still works from the parsed content.
7. The existing recording flow still works.
8. The existing reflection flow still works.
9. Saved files still contain the correct module, station title, scenario, and four questions.
```

## Implementation Loop

When implementing this change:

```text
1. First update the home screen module card display.
2. Then update practice setup UI to one textarea.
3. Then implement the station text parser.
4. Then connect parsed data to the existing station flow.
5. Then run one full manual station and inspect the saved files.
```

If any part fails:

```text
1. Identify whether the failure is UI display, parsing, station flow, or saved output.
2. Re-read the relevant section of this file.
3. Fix that layer only.
4. Re-run the end-to-end criteria.
```
