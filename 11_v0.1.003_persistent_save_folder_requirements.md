# V0.1.003 Persistent Save Folder Requirements

## Purpose

This change makes the selected save folder persistent across browser sessions.

After the user selects a save folder once, the app should remember that folder in the browser so the user does not need to browse for it again every time they reopen the tool.

The user experience should be:

```text
Open the tool
See the previously selected save folder name
Confirm or reconnect permission if needed
Continue practising without manually selecting the folder again
```

## Current Behaviour

The app currently stores the selected folder handle only in memory.

This means:

```text
1. The user selects a save folder.
2. The app can save sessions during the current browser session.
3. If the page is refreshed, the browser is closed, or the computer is restarted, the selected folder is lost.
4. The user must select the save folder again.
```

## Target Behaviour

After a save folder is selected, the app should persist the folder handle in browser storage.

On later visits, the app should:

```text
1. Load the remembered folder handle.
2. Show the remembered folder name in the Save Folder / Settings area.
3. Check whether read/write permission is still granted.
4. If permission is granted, mark the save folder as ready.
5. If permission is not granted, show a clear reconnect/confirm access action.
6. Use the remembered folder for session saving once permission is available.
```

The user should still be able to change the save folder at any time.

## Technical Approach

Use IndexedDB to store the `FileSystemDirectoryHandle`.

Suggested storage:

```text
Database name: mmi-practice-tool
Object store: settings
Key: saveDirectoryHandle
Value: FileSystemDirectoryHandle
```

When the user selects a folder with:

```text
window.showDirectoryPicker()
```

the app should:

```text
1. Save the directory handle in app state.
2. Persist the directory handle to IndexedDB.
3. Show the selected folder name.
```

On app startup, the app should:

```text
1. Open IndexedDB.
2. Read the saved directory handle.
3. If a handle exists, place it back into app state.
4. Show the folder name as remembered.
5. Check permission with queryPermission({ mode: "readwrite" }).
```

If permission is not granted, request permission only from a user gesture, such as:

```text
Reconnect folder
Confirm folder access
```

Do not call `requestPermission()` automatically on page load, because browsers may block permission prompts that are not triggered by a user action.

## Save Folder UI States

The Save Folder / Settings area should support these states:

```text
No save folder selected
Save folder ready: [folder name]
Folder remembered, permission needed: [folder name]
Save folder unavailable, please choose again
```

Suggested buttons:

```text
Select save folder
Change save folder
Reconnect folder
```

## Same-Origin Constraint

The remembered folder handle belongs to the browser origin.

For this project, that means the remembered folder is tied to the exact local server origin, for example:

```text
http://localhost:5181
```

If the user opens the app from a different port, such as:

```text
http://localhost:5182
```

Chrome may treat it as a different website and the remembered folder may not be available.

The app does not need to solve cross-origin persistence in this version. It should simply work reliably when the same local origin is used.

## Completion Criteria

This change is successful when:

```text
1. Selecting a save folder stores the directory handle in IndexedDB.
2. Refreshing the page restores the remembered folder name.
3. Closing and reopening the browser on the same origin restores the remembered folder name.
4. If permission is still granted, the app can save without reselecting the folder.
5. If permission is not granted, the app shows a reconnect/confirm access action.
6. Reconnecting folder permission allows saving to the remembered folder.
7. Changing the save folder updates both app state and the stored IndexedDB handle.
8. Existing session saving still writes question.txt, answer.webm, reflection.md, metadata.json, and any reflection audio files.
9. If IndexedDB storage fails, the user can still select a folder for the current session.
```

## Failure Handling

If IndexedDB is unavailable or fails:

```text
1. Show a non-blocking message that the folder cannot be remembered.
2. Allow the user to select a folder for the current session.
3. Do not prevent normal saving during the current session.
```

If the remembered handle cannot be used:

```text
1. Show "Save folder unavailable, please choose again."
2. Let the user select a new folder.
3. Replace the stored handle with the new valid handle.
```

If permission is denied:

```text
1. Show that permission is needed before saving.
2. Keep all current station and reflection data intact.
3. Let the user retry reconnecting or choose a different folder.
```

If the user changes port/origin and the remembered folder is missing:

```text
1. Treat it as no save folder selected.
2. Let the user select a folder again.
3. Do not show a confusing error.
```

## Implementation Loop

```text
1. Read the existing storage and settings implementation.
2. Add small IndexedDB helpers for reading and writing the directory handle.
3. Persist the handle after folder selection.
4. Restore the handle on app startup.
5. Add folder permission status to app state.
6. Update Save Folder UI states and reconnect action.
7. Ensure saving uses the restored handle after permission is granted.
8. Add or update tests where practical.
9. Manually verify refresh/reopen behaviour in Chrome or Edge on the same localhost port.
10. Re-check every completion criterion.
```
