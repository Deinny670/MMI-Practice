# V0.1.006 Whisper Answer Transcript Requirements

## Purpose

Station recordings currently save only audio (`answer.webm`). There is no transcript of what the candidate said.

This change adds speech-to-text transcription of the spoken station answers using **OpenAI Whisper**.

The OpenAI API source / credentials will be provided later by the product owner. This requirement defines the product behaviour and integration shape now, without hard-coding a secret or assuming the final credential delivery method.

## Current Behaviour

After a station:

```text
1. The app holds answer audio in memory.
2. On save, it writes answer.webm.
3. No transcript file is created.
4. Reflection and later review depend on listening to audio only.
```

This makes later AI or human review slower and makes text-based feedback harder.

## Target Behaviour

After the spoken station answers are available, the app should produce a transcript of the answer recording via OpenAI Whisper.

Required user-facing outcomes:

```text
1. A transcript is generated from the station answer audio.
2. The transcript is available in the session output after save.
3. metadata.json references the transcript file.
4. If transcription fails, the session can still save audio and reflection, with a clear transcript error state.
```

Preferred session output addition:

```text
answer-transcript.md
```

or:

```text
answer-transcript.txt
```

Prefer Markdown if the transcript includes question headings; plain text is acceptable if simpler.

Suggested transcript structure:

```text
# Answer Transcript

## Question 1
[transcribed text]

## Question 2
[transcribed text]

## Question 3
[transcribed text]

## Question 4
[transcribed text]
```

If Whisper returns one continuous transcript and reliable per-question splitting is not yet available, save the full transcript as a single body and note that per-question segmentation is best-effort.

When transcript generation timing is practical:

```text
Start after answer recording completes
Show a clear Transcribing... state on the reflection screen
Allow the user to continue writing reflection while transcription runs
Show Transcript ready or Transcript failed without blocking reflection typing
```

The transcript should also be reviewable on the reflection screen once ready, alongside audio review if that feature exists.

## Technical Approach

Use OpenAI Whisper for speech-to-text.

Integration constraints:

```text
1. Do not hard-code API keys in source files.
2. Read credentials / endpoint configuration from a source that will be provided later.
3. Keep the Whisper client behind a small adapter so the credential source can change without rewriting the reflection or storage flow.
```

Placeholder configuration expectation until the owner provides the source:

```text
OPENAI_API_KEY or equivalent runtime config
model: whisper-1 unless a newer Whisper-compatible OpenAI speech model is specified later
input: station answer audio Blob / file
output: plain transcript text
```

Because this app is a local browser HTML tool, the implementing AI must choose a safe integration path once the OpenAI source is provided. Acceptable directions:

```text
A small local helper/proxy that holds the key off the client bundle
or
a documented local config mechanism that never commits secrets
```

Do not commit `.env` secrets. `.env` remains gitignored.

Likely files / areas:

```text
src/storage.mjs
src/app.mjs
src/core.mjs
new small transcript/whisper helper module
test coverage for transcript formatting and metadata references
01_storage_model_requirements.md as base storage reference
```

Storage / metadata additions:

```json
{
  "files": {
    "question": "question.txt",
    "audio": "answer.webm",
    "reflection": "reflection.md",
    "transcript": "answer-transcript.md"
  },
  "transcript": {
    "status": "ready",
    "provider": "openai-whisper",
    "model": "whisper-1"
  }
}
```

If transcription failed:

```json
{
  "transcript": {
    "status": "failed",
    "provider": "openai-whisper",
    "error": "short reason"
  }
}
```

Do not invent a fake transcript on failure.

## Out Of Scope For This Requirement

```text
Final OpenAI credential delivery details will be provided later
Translation to other languages
Realtime partial captions during the timed answer itself
Transcribing reflection voice notes
```

Reflection voice-note transcription may be a later change.

## Completion Criteria

1. After station answer audio exists, the app can send that audio to OpenAI Whisper through the configured source.
2. A successful transcription writes `answer-transcript.md` or `answer-transcript.txt` into the session folder on save.
3. `metadata.json` references the transcript file and provider/status.
4. The reflection UI shows transcription progress and ready/failed state.
5. The user can read the transcript in the reflection flow once it is ready, without needing to open the folder first.
6. If Whisper/API config is missing, the UI explains that transcription is unavailable and still allows normal save of audio/reflection files.
7. If Whisper fails at runtime, no success state is shown for transcription, and no fabricated transcript is saved.
8. API keys are not committed to the repository.
9. Existing required session files still save correctly when transcription is skipped or fails.

## Failure Handling

If the OpenAI source/key is not configured yet:

```text
1. Keep station practice and save working.
2. Show that transcript generation is not configured.
3. Do not block Save Session.
```

If the Whisper request fails:

```text
1. Show Transcript failed with a short reason.
2. Preserve audio Blob, reflection text, and reflection voice notes.
3. Allow retry if practical once config/network is fixed.
4. Save the session without a transcript file, or with explicit failed status only in metadata, according to the implementation choice above.
```

If audio format is rejected by the API:

```text
1. Convert or wrap the Blob into an accepted format if practical.
2. Otherwise report a clear format error.
3. Do not lose the original answer.webm.
```

## Implementation Loop

1. Read this file and `01_storage_model_requirements.md`.
2. Add a Whisper adapter with config injected from the future OpenAI source.
3. Trigger transcription after answer recording completes.
4. Surface transcript status on the reflection screen.
5. Save transcript file + metadata references on successful transcription.
6. Verify missing-config and failed-request behaviour.
7. Re-check every completion criterion.
8. Report exactly what changed, what remains waiting on the OpenAI source, and what was verified.
