# V0.1.005 Reflection Response Review Requirements

## Purpose

During reflection, the user currently cannot review their own spoken station responses. They can only listen after saving the session and opening `answer.webm` from the local folder.

This change adds in-session response review on the reflection screen so the user can replay their answers while writing reflection notes, before save.

Scope is limited to reflection-time review of the station answer recording. It does not add Whisper transcripts; that is a separate change.

## Current Behaviour

After Q4 answer ends, the reflection screen shows:

```text
Station summary
Four reflection prompts
Optional voice reflection controls
Save Session / navigation
```

The spoken station answers exist in memory as the `answer.webm` Blob, but the reflection UI does not let the user play them back.

As a result:

```text
1. The user must remember what they said.
2. Reflection quality drops for longer multi-question stations.
3. Playback is only practical after save, outside the reflection flow.
```

## Target Behaviour

On the reflection screen, before saving, the user must be able to review their spoken responses.

Minimum required review affordances:

```text
1. Play the full station answer recording.
2. See clear controls for play / pause / scrub or restart.
3. Know that this review is available before Save Session.
```

Preferred per-question review:

```text
1. Show Question 1-4 labels with the question text.
2. Let the user jump to or play each answer segment.
3. Use the existing audioSegments timing windows for q1-q4.
```

If exact per-question seeking is difficult in the first pass, full-recording playback is required; per-question jump controls should still be implemented if the existing segment metadata makes it practical.

Review must work while reflection text and optional reflection voice notes remain editable.

Save behaviour stays the same: review does not require saving first.

## Technical Approach

Use the in-memory answer audio Blob already produced by the station recorder.

Likely files:

```text
src/app.mjs
src/styles.css
src/core.mjs for audioSegments helpers if needed
10_v0.1.002_reflection_navigation_audio_requirements.md
06_reflection_flow_requirements.md
```

Suggested approach:

```text
1. Keep the completed answer Blob in app state until the session is discarded or a new station starts.
2. Create an object URL from the Blob for an HTML audio element on the reflection screen.
3. Revoke the object URL when leaving reflection or replacing the recording.
4. Render a Response Review section above or beside the reflection prompts.
5. For per-question review, seek using audioSegments:
   q1: 0-60
   q2: 75-135
   q3: 150-210
   q4: 225-285
   when continuous recording includes prep gaps as currently modeled.
```

UI guidance:

```text
One clear Response Review section
Show current question label when playing a segment
Do not bury playback behind Save Session
Do not require opening the local folder
```

Do not replace or remove existing reflection prompts, navigation, or reflection voice recording.

## Completion Criteria

1. After station completion, the reflection screen includes a Response Review section.
2. The user can play the station answer audio before clicking Save Session.
3. Play / pause controls work on the in-memory recording.
4. The user can still type reflection answers while review controls are visible.
5. Optional reflection voice recording still works.
6. Saving is not required before playback.
7. If per-question controls are present, each jumps to the correct answer segment window.
8. Leaving reflection / starting a new station does not leave a leaked object URL in a way that breaks later sessions.
9. Existing save output still writes `question.txt`, `answer.webm`, `reflection.md`, `metadata.json`, and any reflection audio files.

## Failure Handling

If the answer Blob is missing on the reflection screen:

```text
1. Show a clear message that spoken answers are unavailable for review.
2. Keep reflection text editable.
3. Do not block Save Session if other required save inputs are present according to existing rules.
4. Investigate why station completion advanced without a recording Blob.
```

If audio playback fails in the browser:

```text
1. Show a non-blocking playback error.
2. Preserve reflection text and reflection voice notes.
3. Still allow retry of playback from the same Blob.
```

If per-question seeking is inaccurate:

```text
1. Keep full-recording playback working.
2. Re-check audioSegments against the recording model.
3. Do not invent new timing values that disagree with metadata.
```
