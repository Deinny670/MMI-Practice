# V0.1.007 Reflection Review Transcript Patch Requirements

## Purpose

V0.1.005 defined reflection-time **audio** review only, and explicitly deferred transcripts.

V0.1.006 later added Whisper transcripts and said the transcript should be reviewable on the reflection screen alongside audio review.

This patch updates the V0.1.005 Response Review design so reflection review is **audio + transcript ready**, not audio-only. It does not re-specify Whisper integration; it patches the review UI/state contract so V0.1.005 and V0.1.006 compose cleanly.

Scope:

```text
Patch reflection Response Review to host transcript states and content
Define how audio review and transcript review share one section
Keep Whisper provider/config details in V0.1.006
```

## Current Behaviour

As written today:

```text
V0.1.005: Response Review = play answer.webm / optional per-question seek
V0.1.005: explicitly out of scope for Whisper transcripts
V0.1.006: transcript appears on reflection when ready, "alongside audio review if that feature exists"
```

The gap:

```text
1. V0.1.005 does not reserve UI space or state for transcript idle / loading / ready / failed / unavailable.
2. An implementer of V0.1.005 can hard-wire an audio-only panel that is awkward to extend.
3. Per-question audio review and per-question transcript headings may diverge unless the patch defines one shared review model.
```

## Target Behaviour

The reflection **Response Review** section must support both:

```text
1. Spoken answer audio review (from V0.1.005)
2. Answer transcript review (from V0.1.006), when a transcript exists or is in progress
```

### Shared review section

Response Review remains one section, not two disconnected panels buried in different places.

It should present:

```text
Response Review
  Audio controls (full recording + optional Q1-Q4 jump)
  Transcript status + transcript body when available
```

### Transcript states inside Response Review

The section must be able to show these transcript states without redesigning the whole reflection screen later:

```text
unavailable / not configured
transcribing...
ready
failed
```

When transcript is ready:

```text
1. Show the transcript text inside Response Review.
2. Prefer the same Question 1-4 structure used for audio segment review when per-question transcript parts exist.
3. Let the user read the transcript while continuing to edit reflection prompts.
4. Do not require Save Session before reading the transcript.
```

When transcript is still loading:

```text
1. Keep audio review usable immediately.
2. Show Transcribing... in the transcript area.
3. Do not block reflection typing or audio playback.
```

When transcript is unavailable or failed:

```text
1. Keep audio review fully usable.
2. Show a short non-blocking status message.
3. Do not invent placeholder transcript text.
```

### Per-question alignment

If both per-question audio controls and per-question transcript headings are present, they should use the same question order and labels:

```text
Question 1
Question 2
Question 3
Question 4
```

Selecting or focusing a question for audio review should make it easy to find the matching transcript block when both exist. Exact auto-scroll is preferred but not mandatory in this patch; shared labelling and order are mandatory.

## Technical Approach

Treat this as a patch on top of:

```text
update/13_v0.1.005_reflection_response_review_requirements.md
update/14_v0.1.006_whisper_transcript_requirements.md
```

Implementation guidance:

```text
1. Model Response Review state as:
   - answerAudioBlob / object URL / playback position
   - transcriptStatus: unavailable | transcribing | ready | failed
   - transcriptText or per-question transcript parts
   - transcriptError optional short reason
2. Render transcript UI inside the same Response Review container as audio controls.
3. Do not build a second top-level "Transcript" page for this flow.
4. Keep Whisper request/adapter logic owned by V0.1.006.
5. Keep audio Blob playback owned by V0.1.005, extended only as needed for shared layout/state.
```

Likely files:

```text
src/app.mjs
src/styles.css
any transcript helper introduced by V0.1.006
```

UI constraints:

```text
Audio remains usable even when transcript is missing
Transcript appears in-place when ready
One Response Review composition, not card spam or detached floating panels
```

What this patch does **not** change:

```text
Whisper provider choice
API key / OpenAI source delivery
Transcript file naming in the saved session folder
Reflection prompt wording
Reflection voice-note recording
```

## Relationship To Prior Requirements

After this patch:

```text
V0.1.005 remains the source for audio playback behaviour
V0.1.006 remains the source for Whisper generation, save files, and metadata
V0.1.007 is the composition patch: Response Review must host both
```

Where V0.1.005 said transcripts were out of scope, this patch supersedes that boundary for the Response Review UI only.

## Completion Criteria

1. Response Review is specified/implemented as one section that can show audio controls and transcript status/content together.
2. Transcript states `unavailable`, `transcribing`, `ready`, and `failed` have a defined place in Response Review.
3. When transcript status is `ready`, the user can read transcript text on the reflection screen before save.
4. When transcript is loading, failed, or unavailable, audio review still works.
5. Reflection text editing remains usable during all transcript states.
6. Per-question audio labels and per-question transcript headings use the same Question 1-4 order when both exist.
7. No second disconnected transcript-only surface is required for the basic reflection review flow.
8. V0.1.006 save/metadata transcript rules remain unchanged by this patch.
9. V0.1.005 audio playback completion criteria remain satisfied.

## Failure Handling

If transcript state is missing from the Response Review implementation:

```text
1. Treat this patch as failed even if audio playback works.
2. Re-read Target Behaviour and add the transcript status area to the same section.
```

If transcript UI blocks audio playback:

```text
1. Separate the transcript status/body from the audio controls inside the same section.
2. Ensure audio can start while transcript is still transcribing or failed.
```

If implementers create a separate transcript page instead of patching Response Review:

```text
1. Reject that as out of scope for this patch.
2. Move transcript display back into Response Review.
```

## Implementation Loop

1. Read this file together with V0.1.005 and V0.1.006.
2. Update Response Review UI/state to include transcript status and body slots.
3. Wire those slots to the V0.1.006 transcript states when that feature is present.
4. Verify audio-only behaviour still works when transcript is unavailable.
5. Verify ready/loading/failed transcript states appear inside Response Review.
6. Re-check every completion criterion.
7. Report exactly what was patched in the review composition and what remains owned by V0.1.006.
