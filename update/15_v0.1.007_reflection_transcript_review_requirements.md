# V0.1.007 Reflection Transcript Review Requirements

## Purpose

After station completion, the user should be able to read their answer transcript on the reflection screen while writing reflection notes.

V0.1.005 adds audio playback review. V0.1.006 generates and saves Whisper transcripts. This requirement implements transcript review in the reflection flow itself: the user can read the transcript before save, without opening the session folder.

## Current Behaviour

Depending on prior changes:

```text
V0.1.005: user can play answer audio during reflection
V0.1.006: Whisper can produce a transcript and save it with the session
```

Even with those pieces, the reflection experience is incomplete if transcript text is only useful after save, or only exists as a file reference.

The user still cannot reliably:

```text
1. Read what they said while reflecting
2. Compare spoken answers to reflection prompts without leaving the flow
3. Use per-question transcript text next to the matching question/audio review
```

## Target Behaviour

On the reflection screen, once a transcript is available, the user must be able to read it in-session.

Required behaviour:

```text
1. Show the answer transcript on the reflection screen before Save Session.
2. Keep reflection prompts editable while the transcript is visible.
3. Keep audio review usable at the same time when V0.1.005 is present.
4. Show clear transcript status while generation is in progress or has failed.
```

### Transcript display

When transcript status is ready:

```text
Display the transcript text on the reflection screen
Prefer Question 1-4 headings when per-question parts exist
Allow scrolling/reading without leaving reflection
Do not require opening answer-transcript.md from disk first
```

Suggested layout when audio review also exists:

```text
Response Review
  Audio playback controls
  Transcript text / status
Reflection prompts...
```

If audio review is not yet present, still show transcript review on the reflection screen on its own.

### Status behaviour

```text
transcribing...  -> show progress; do not block typing or audio playback
ready            -> show transcript text
failed           -> show short error; keep audio/reflection usable
unavailable      -> show that transcript is not available; keep audio/reflection usable
```

### Per-question alignment

When both per-question audio controls and per-question transcript headings exist, use the same order and labels:

```text
Question 1
Question 2
Question 3
Question 4
```

## Technical Approach

Implement transcript review as a reflection-screen feature that consumes transcript state produced by V0.1.006.

Likely files:

```text
src/app.mjs
src/styles.css
transcript helper / state from V0.1.006
```

Required state on the reflection screen:

```text
transcriptStatus: unavailable | transcribing | ready | failed
transcriptText or per-question transcript parts
transcriptError optional short reason
```

Wire that state into reflection UI:

```text
1. After answer recording completes, V0.1.006 starts transcription.
2. Reflection screen reads the live transcript status/text from app state.
3. When ready, render the transcript in the review area.
4. On save, V0.1.006 still writes the transcript file and metadata; this requirement does not change file format.
```

Do not:

```text
Hard-code fake transcript content
Block Save Session because transcript is still loading
Replace audio review
Re-specify Whisper API credentials or provider details already owned by V0.1.006
```

## Completion Criteria

1. When transcript status is `ready`, the reflection screen shows the transcript text before save.
2. The user can read the transcript while editing reflection prompts.
3. While status is `transcribing`, the reflection screen shows a clear in-progress state and remains usable.
4. While status is `failed` or `unavailable`, the reflection screen shows a short non-blocking message and remains usable.
5. Audio review from V0.1.005 still works when present.
6. Per-question transcript headings, when present, follow Question 1-4 order.
7. Saving is not required before reading a ready transcript.
8. No fabricated transcript is shown on failure.
9. Existing save behaviour for transcript files/metadata from V0.1.006 remains intact.

## Failure Handling

If transcript state never reaches the reflection UI:

```text
1. Trace from V0.1.006 transcript completion into reflection render state.
2. Fix the state wiring; do not only save the file without on-screen review.
```

If transcript UI blocks reflection typing:

```text
1. Keep transcript in a readable review region separate from the prompt textareas.
2. Re-test typing during transcribing and ready states.
```

If only the saved folder contains the transcript and the reflection screen does not:

```text
1. Treat this requirement as failed.
2. Surface the in-memory/ready transcript on the reflection screen.
```

6. Re-check every completion criterion.
