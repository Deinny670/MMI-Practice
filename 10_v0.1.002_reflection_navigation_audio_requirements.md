# V0.1.002 Reflection Navigation And Voice Reflection Requirements

## Purpose

This change improves the post-station reflection experience.

After completing a station, the user should be able to:

```text
Return to the home screen or continue to another station
Answer softer, more useful reflection prompts
Optionally record spoken reflection notes for each reflection prompt
Save those reflection voice notes into the local session folder
```

## Current Behaviour

The reflection screen currently:

```text
Shows four text reflection prompts
Allows saving the session
Does not provide a clear way back to the home screen after station completion
Does not support audio reflection recordings
```

The current prompts are:

```text
1. What was the core issue or conflict in this station?
2. What did I do well in my answer?
3. What would I change if I answered again?
4. Did I show structure, empathy, professionalism, and a clear next step?
```

## Target Behaviour

## Change 1: Add Reflection Navigation

After station completion, the reflection screen should include clear navigation controls.

At minimum, provide:

```text
Back to Home
```

After saving successfully, the user should still be able to return home and start another station.

The navigation should preserve the user's typed reflection text unless the user intentionally leaves the current session.

## Change 2: Update Reflection Prompts

Replace the current reflection prompts with four revised prompts:

```text
1. Briefly summarize how you approached this station.
2. What did I do well, and what would I change if I answered again?
3. Did I show structure, empathy, professionalism, and a clear next step?
4. What is one specific thing I should practise or improve in the next station?
```

The second prompt merges the previous "did well" and "change next time" questions.

The fourth prompt should focus the user on the next concrete improvement, not vague self-criticism.

## Change 3: Add Optional Voice Reflection Recordings

Each of the four reflection prompts should include a small microphone button at the bottom-right of that prompt's response area.

The user can press the microphone button to record a spoken reflection note for that specific prompt.

Expected behaviour:

```text
1. Press microphone button to start recording for that prompt.
2. Press again to stop recording.
3. Only one reflection prompt should record at a time.
4. The UI should show which prompt is currently recording.
5. Recorded reflection audio should be kept until session save.
```

The text response remains available. Voice reflection is additional.

## Technical Approach

## Reflection Prompt Data

Update the prompt data model so the four reflection prompts have stable keys and labels.

Suggested keys:

```text
summary
answerReview
structureCheck
nextStep
```

## Reflection Audio File Names

When a reflection audio recording exists, save it as a separate `.webm` file in the session folder.

Use readable, filesystem-safe filenames based on the prompt title:

```text
reflection-01-summary.webm
reflection-02-answer-review.webm
reflection-03-structure-empathy-professionalism-next-step.webm
reflection-04-next-station-improvement.webm
```

The exact slug may differ, but it must be readable and stable.

## Storage

The base session files remain required:

```text
question.txt
answer.webm
reflection.md
metadata.json
```

Reflection audio files should be saved in the same session folder when present.

`metadata.json` should include reflection audio file references.

Example:

```json
{
  "files": {
    "question": "question.txt",
    "audio": "answer.webm",
    "reflection": "reflection.md",
    "reflectionAudio": {
      "summary": "reflection-01-summary.webm",
      "answerReview": "reflection-02-answer-review.webm"
    }
  }
}
```

## Completion Criteria

This change is successful when:

```text
1. The reflection screen has a clear Back to Home or equivalent navigation control.
2. The four reflection prompts use the revised wording.
3. The previous separate "What did I do well" and "What would I change" prompts are merged.
4. Each reflection prompt has a microphone button at the bottom-right of the response area.
5. Pressing a reflection microphone button starts recording for that prompt.
6. Pressing it again stops recording and keeps the audio for that prompt.
7. Only one reflection prompt records at a time.
8. Saving a session still writes question.txt, answer.webm, reflection.md, and metadata.json.
9. Any recorded reflection voice notes are saved as additional .webm files in the same session folder.
10. metadata.json references the saved reflection voice note files.
11. Existing station answer recording still works.
```

## Failure Handling

If reflection microphone permission is denied:

```text
1. Show a clear error message.
2. Keep the text reflection fields editable.
3. Do not block text-only saving.
```

If a reflection audio recording fails:

```text
1. Tell the user which prompt failed to record.
2. Preserve existing text and other recorded reflection audio.
3. Allow the user to retry that prompt.
```

If saving reflection audio fails:

```text
1. Do not show a full success message.
2. Report which reflection audio file failed.
3. Keep the reflection screen open so the user can retry saving.
```
